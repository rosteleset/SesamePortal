# Интеграция стороннего приложения с SesamePortal

Документ описывает подключение стороннего приложения к порталу SesamePortal:
приложение отправляет номер телефона пользователя, портал возвращает
**постоянный токен** (static token) этого пользователя, и далее приложение
использует этот токен для вызовов JSON API (`/api/portal/v1/...`).

Сам JSON API детально описан в `docs/SESAME-PORTAL-API.ru.md`. Здесь описан
только сценарий получения токена по номеру телефона.

## Сценарий

```text
Стороннее приложение                    SesamePortal
        │                                        │
        │  POST /api/portal/v1/auth/token-by-phone│
        │  X-App-Key: <секрет>                   │
        │  {"phone": "+7 900 123-45-67"}          │
        │───────────────────────────────────────>│
        │  200 {"token": "sp_…", user_id, role}  │
        │<───────────────────────────────────────│
        │                                        │
        │  GET /api/portal/v1/me                 │
        │  Authorization: Bearer sp_…            │
        │───────────────────────────────────────>│
        │  200 {…}                               │
        │<───────────────────────────────────────│
```

1. Стороннее приложение один раз получает постоянный токен пользователя,
   указав его номер телефона.
2. Токен не меняется при последующих запросах (пока его не отзовёт
   администратор на портале). Его можно безопасно кэшировать в приложении.
3. Дальше приложение обращается к JSON API как «пользователь»: полные права
   пользователя, по идентичному механизму `Authorization: Bearer <static-token>`
   (см. `docs/SESAME-PORTAL-API.ru.md`).

## Настройка на портале

Администратор включат интеграцию в панели
**«Настройки → Интеграция стороннего приложения»** (`/admin/settings`):

1. Сгенерировать или вписать **ключ интеграции** (от 16 до 64 символов:
   латинские буквы, цифры, `-` и `_`).
2. Нажать **Сохранить**.
3. Скопировать URL эндпоинта для получения токена и передать стороннему
   приложению вместе с ключом.

Пока ключ не задан, эндпоинт возвращает `503 integration_disabled`.

У пользователя, для которого запрашивается токен, в профиле должен быть
заполнен номер телефона. Номера **не** должны повторяться у разных
пользователей.

## Эндпоинт получения токена

### `POST /api/portal/v1/auth/token-by-phone`

Принимает JSON

```json
{
  "phone": "+7 900 123-45-67"
}
```

Авторизация стороннего приложения — заголовок

```text
X-App-Key: <ключ интеграции>
```

(поле `app_key` в теле JSON — альтернативный способ передачи ключа, но
рекомендуется заголовок).

### Нормализация номера

Номер приводится к 11 цифрам (удаляются все нецифровые символы; ведущая
`8` заменяется на `7`), например:

```text
+7 900 123-45-67  →  79001234567
89001234567       →  79001234567
+7(900)123-45-67  →  79001234567
```

Совпадение ищется с заполненным в профиле пользователя номером.

### Ответы

`200 OK` — токен выдан (или выдан ранее и возвращён повторно):

```json
{
  "token": "sp_…",
  "user_id": 7,
  "login": "79001234567",
  "role": "user"
}
```

Замечание: `token` — постоянный; повторные запросы для того же номера
возвращают тот же токен, пока его не отзовут.

`401 Unauthorized` — неверный или отсутствующий ключ интеграции:

```json
{
  "error": { "code": "unauthorized", "message": "Invalid external app key" }
}
```

`422` — некорректный номер телефона:

```json
{
  "error": { "code": "validation_failed", "message": "phone is required and must be a valid russian number" }
}
```

`404` — пользователь с таким номером не найден или заблокирован, либо номер
дублируется у нескольких пользователей (специально не детализируется):

```json
{
  "error": { "code": "not_found", "message": "User not found" }
}
```

`503` — интеграция не настроена (ключ интеграции отсутствует):

```json
{
  "error": { "code": "integration_disabled", "message": "External API integration is not configured" }
}
```

`405` — метод не `POST`.

## Примеры

Получить токен:

```bash
curl -sS -X POST \
  -H 'Content-Type: application/json' \
  -H 'X-App-Key: my_app_secret' \
  -d '{"phone": "+7 900 123-45-67"}' \
  https://portal.example.com/api/portal/v1/auth/token-by-phone
```

Далее использовать токен для JSON API:

```bash
TOKEN=sp_…   # из ответа выше

curl -sS -H "Authorization: Bearer $TOKEN" \
  https://portal.example.com/api/portal/v1/me

curl -sS -H "Authorization: Bearer $TOKEN" \
  https://portal.example.com/api/portal/v1/cameras
```

## Безопасность и отзыв

- Токен имеет **полные права владельца** аккаунта, поэтому:
  - ключ интеграции и полученные токены считаются секретными;
  - «номер → токен» защищено ключом интеграции, утечка номера без ключа
    не позволяет получить доступ.
- Отозвать токен пользователя можно в админке или через JSON API:
  `DELETE /api/portal/v1/users/{id}/static-token` (от имени администратора).
- После отзыва и повторного запроса к эндпоинту будет выпущен новый токен.
- Серия выпусков/запросов токена логируется в журнале аудита
  (`user.static_token.issue`, `user.static_token.request`).
